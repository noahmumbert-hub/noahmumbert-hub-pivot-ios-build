## Fresh installs and upgrades

The installer replaces the 1.18.4 app bundle. 1.18.5 cannot read it afterward, so even previously bundled artwork requires a one-time internet download on a direct upgrade. The user acknowledged this tradeoff. No intermediate migration release is required or assumed. Existing photos/placeholders, ride information and live-data controls remain available when an illustration has not been saved. On-demand thumbnail/detail requests and Settings → Artwork downloads provide unavailable, downloading, explicit retry, pause and resume states. Credits for an illustration appear with the verified illustration rather than the temporary photo fallback.

Every version includes the complete accepted catalogue; no installed intermediate version or mutable remote manifest is needed. File identity is the exact park ID, ride ID, variant and expected SHA-256. Persistent filenames use content hashes rather than app versions or source URLs. A later catalogue can point to another immutable commit and still reuse identical already-verified bytes. Valid older downloads are retained and counted against the storage bound, including assets not requested by the current screen.

## Three independent storage budgets

* **IPA:** The previous IPA is 98,033,521 bytes with 6,824,079 bytes of headroom. Its JPEG members occupy 89,661,086 compressed bytes and its old index 301,226. The new complete metadata is 3,012,718 uncompressed bytes, approximately 649,662 bytes with deflate. Removing JPEG members yields an approximately **8,720,871-byte IPA before added executable code and new ZIP overhead**. This is an estimate, not an archive result. The actual Release IPA must pass a **32 MiB minimum headroom** gate below 104,857,600 bytes. No size claim qualifies publication until the fresh archive is measured.
* **Persistent device artwork:** Up to **384 MiB**, without preallocation or automatic eviction of valid originals. The current set uses 218,526,843 bytes (about 208.4 MiB), leaving 184,126,341 bytes (about 175.6 MiB) within that policy for future assets. Reaching the quota pauses additions; it never silently deletes artwork.
* **Free device space and temporary writes:** Before each request and before committing it, the app checks the actual volume capacity and preserves a **512 MiB policy reserve**, plus twice the outstanding original byte reservations for bounded temporary writes. Originals are no larger than 350,000 bytes by schema and at most two transfers run, so these reservations are bounded. A file is length/hash/dimension checked in memory, written to a known temporary name, read back and reverified, then renamed in the same directory. Incomplete temporary files are cleaned on a later launch. Existing valid files bypass new-download storage checks and remain readable offline even when space is low. The user's physical free space and SideStore/iOS signing/install workspace are uninspected; the reserve is not a guarantee for every future update.

The directory is Application Support, not Caches/URLCache, and is excluded from backup because the originals are independently redownloadable. No app-version component enters the persistent key. Missing or uninspectable capacity fails safely; write-out-of-space or partial-write failures never publish a completed asset. Data/UIImage work runs away from the UI, with the existing 20 MiB decoded-image NSCache retained. No background-download entitlement is added. Artwork pauses when the app backgrounds and can resume while open. The privacy manifest records disk-capacity use for checking file writes (E174.1) and existing app-owned defaults (CA92.1), without adding a permission prompt or entitlement.
